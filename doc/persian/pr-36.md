# گزارش PR شمارهٔ ۳۶: Value Objectهای اعتبارسنجی‌شده برای Asset

## خلاصه و هدف

این PR شناسه و نام Asset را از داده‌های ساده به دو نوع دامنه‌ای تغییر می‌دهد: `AssetId` و `AssetName`. هر نوع هنگام ساخته‌شدن مقدار نامعتبر را رد می‌کند و مقدار معتبر را بدون تغییر نگه می‌دارد. هدف، متمرکزکردن اعتبارسنجی و مقایسهٔ مقداری است، بدون تغییر قرارداد عمومی ساخت Asset.

این تغییر قواعدی تازه برای Asset تعریف نمی‌کند: شناسه باید `Guid` غیرخالی باشد و نام نباید خالی یا فقط شامل فاصله باشد. نام trim یا نرمال نمی‌شود و محدودیت طول یا یکتایی ندارد.

## چرا این پیاده‌سازی؟

`AssetId` و `AssetName` به‌صورت `sealed record` و با ویژگی‌های فقط‌خواندنی ساخته شده‌اند. برابری record بر اساس مقدار است؛ بنابراین دو شناسه با `Guid` یکسان یا دو نام با متن دقیقاً یکسان برابرند. در مقابل، `Bicycle` و `bicycle`، نام trim‌شده و trim‌نشده، یا دو نمایش Unicode متفاوت برابر نیستند. این مقایسه به‌خودی‌خود یکتایی شناسه یا نام را تضمین نمی‌کند.

سازندهٔ خصوصی Asset این نوع‌ها را می‌سازد، در حالی که ویژگی‌های عمومی و کارخانهٔ `Asset.Create` همان قرارداد قبلی را نگه می‌دارند. کارخانه همچنان خطاهای دامنه‌ای را برمی‌گرداند و در صورت نامعتبر بودن هر دو ورودی، ابتدا شناسه بررسی می‌شود. سازنده‌های عمومی value objectها، برعکس، از قرارداد استثناهای guard استفاده می‌کنند.

`ToString()` در هر دو نوع فقط نام نوع را برمی‌گرداند تا قالب‌بندی پیش‌فرض record مقدار را آشکار نکند. این محافظت مانع دسترسی مستقیم به `Value` یا ثبت آگاهانهٔ آن توسط فراخواننده نمی‌شود؛ کد مصرف‌کننده همچنان باید از ثبت نام‌های حساس خودداری کند.

## گزینه‌ها و ملاحظات طراحی

شرط‌های دستی می‌توانستند وابستگی به guard را حذف کنند، اما ADR-0005 استفادهٔ محدود از `Ardalis.GuardClauses` را پذیرفته است. بیرون‌دادن استثنا از `Asset.Create` نیز قرارداد نتیجه‌ای موجود را می‌شکست. برای این نیاز، چارچوب عمومی value object یا تبدیل ضمنی، پیچیدگی اضافه می‌کردند بی‌آنکه مزیت مشخصی داشته باشند.

حفظ دقیق متن، رفتار را قابل‌پیش‌بینی نگه می‌دارد و از افزودن قاعدهٔ تأییدنشده جلوگیری می‌کند؛ در عوض، هر نوع نرمال‌سازی، جست‌وجوی بدون حساسیت به حروف یا جلوگیری از نام تکراری باید تصمیم جداگانه‌ای باشد. PR این سیاست‌ها را پیاده‌سازی نمی‌کند.

## ابزارها و بسته‌ها

`Ardalis.GuardClauses` همان وابستگی تأییدشدهٔ قبلی در Domain است؛ PR بستهٔ جدیدی اضافه نمی‌کند و با ADR-0005 سازگار است. برابری و hash code از رفتار recordهای C# می‌آیند. آزمون‌ها با NUnit نوشته شده‌اند.

## اعتبارسنجی و موارد باقی‌مانده

در صفحهٔ [Checks مربوط به PR](https://github.com/mani8785/HomeVault/pull/36/checks)، تنها بررسی CI با نام `Validate` موفق است؛ GitHub زمان اجرای آن را ۵۶ ثانیه نشان می‌دهد. توضیحات PR نیز موفقیت Restore، بررسی فرمت، ساخت Release بدون هشدار یا خطا، ۳۴ آزمون NUnit، اجرای Playground و `git diff --check` را گزارش می‌کنند. این فرمان‌ها در این بررسی دوباره اجرا نشده‌اند.

طبق مستند HV-06، مجموع آزمون‌ها شامل ۷ آزمون معماری، ۱۱ آزمون قبلی ساخت Asset و ۱۶ آزمون جدید value object است. موارد خارج از محدوده همچنان شامل ذخیره‌سازی، مالکیت و دسترسی Vault و رفتارهای بعدی ثبت Asset هستند.
