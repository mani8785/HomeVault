# گزارش PR شمارهٔ ۳۴: واژگان دامنه و مرزهای Aggregate

PR: [#34، واژگان دامنه و مرزهای Aggregate](https://github.com/mani8785/HomeVault/pull/34) | وضعیت: ادغام‌شده

## خلاصه

این PR پنج فایل مستندات را تغییر داد و هیچ کد اجرایی اضافه نکرد. هدفش روشن‌کردن اصطلاحات و مرزهای مسئولیت در HomeVault بود تا پیاده‌سازی قابلیت‌های دامنه بر پایهٔ تصمیم‌های صریح انجام شود.

## هدف

سند اصلی شش مفهوم را تعریف می‌کند: Asset، Vault، ویژگی Asset، Relationship، Evidence و Reminder. همچنین مشخص می‌کند هر کدام چه چیزی را مالک است، چه قواعدی باید رعایت شوند و چه تصمیم‌هایی باید پیش از پیاده‌سازی تأیید شوند. Aggregate مرزی در مدل دامنه است که قواعد داخلی‌اش پس از هر تغییر باید معتبر بمانند.

## چرایی طراحی و جایگزین‌ها

ADR پیشنهاد می‌کند Vault، Asset، Relationship و Reminder ریشه‌های جدا باشند و با شناسه به هم ارجاع دهند. ویژگی‌ها و فرادادهٔ Evidence فعلاً جزو Asset هستند. این مرزبندی از بارگذاری یک گراف بزرگ جلوگیری می‌کند؛ در عوض، هماهنگی بین اجزا را به Application و ذخیره‌سازی می‌سپارد.

قرار دادن همهٔ Assetها زیر Vault یا جاسازی Relationship و Reminder داخل Asset ساده‌تر به نظر می‌رسد، اما می‌تواند بارگذاری غیرضروری و چرخهٔ عمر مستقل دشوارتر ایجاد کند. جداکردن Evidence هم وقتی معنا دارد که چرخهٔ عمر یا اشتراک‌گذاری مستقل پیدا کند؛ در زمان PR چنین نیازی تثبیت نشده بود.

سیاست بایگانی پیشنهادی، همهٔ تغییرات عضویت را هم مسدود می‌کند و لغو دسترسی را ناممکن می‌سازد. بازیابی دسترسی توسط Owner جایگزین معقولی است، اما به استثنای صریح و آزمون‌های اختصاصی نیاز دارد. برای تغییر هم‌زمان بایگانی و ویرایش، بررسی وضعیت و سپس نوشتن کافی نیست؛ عملیات باید هماهنگ شود یا رد و دوباره اعتبارسنجی شود.

## ابزارها و بسته‌ها

این PR بسته یا ابزار جدیدی اضافه نکرد. کتابخانه‌ها می‌توانند اجرای تراکنش و کنترل هم‌زمانی را پشتیبانی کنند، اما جای تصمیم محصول دربارهٔ نقش‌ها، مالکیت یا بایگانی را نمی‌گیرند. انتخاب SQLite و EF Core بعداً در ADR-0017 پذیرفته شد و بخشی از این PR نبود.

## اعتبارسنجی و ریسک‌ها


توضیحات PR گزارش می‌کنند که Restore، بررسی فرمت، ساخت Release بدون خطا یا هشدار، هر ۷ آزمون معماری NUnit، آزمون دستی Playground و `git diff --check` موفق بوده‌اند. صفحهٔ GitHub نیز یک بررسی CI موفق و ادغام PR را نشان می‌دهد؛ این بررسی‌ها را دوباره اجرا نکرده‌ام.

این آزمون‌ها رفتارهای دامنهٔ تازه‌ای را ثابت نمی‌کنند؛ سند هم سناریوها را برای بررسی و آزمون‌های آینده می‌داند. PR تصمیم‌ها را مستند کرد، نه اینکه قابلیت‌هایشان را پیاده‌سازی کند.
