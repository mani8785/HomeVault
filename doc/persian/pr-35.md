# گزارش PR شمارهٔ ۳۵: ساخت اولیه و اعتبارسنجی Asset

## خلاصه و هدف

پیش از این PR، دامنهٔ برنامه عملیات اجرایی نداشت. این تغییر یک Asset را با شناسهٔ `Guid` غیرخالی و نام غیرسفید ایجاد می‌کند. نام معتبر دقیقاً همان‌طور که کاربر فرستاده حفظ می‌شود. ورودی نامعتبر به‌جای خطا یا شیء ناقص، نتیجهٔ مشخصی مانند `EmptyIdentity` یا `BlankName` می‌دهد.

این فقط ساخت در حافظه است: Asset ذخیره نمی‌شود، وجود یا دسترسی به Vault بررسی نمی‌شود و مجوزدهی اضافه نمی‌شود.

## چرا این پیاده‌سازی؟

سازنده خصوصی است تا ساخت Asset از مسیر اعتبارسنجی عبور کند. Guardها به‌ترتیب شناسه و نام را بررسی می‌کنند؛ بنابراین اگر هر دو نامعتبر باشند، `EmptyIdentity` برمی‌گردد. کارخانه فقط استثناهای آرگومان با نام پارامتر مورد انتظار را می‌گیرد و به کد خطای دامنه تبدیل می‌کند. پیام استثنا یا مقدار ورودی نه در نتیجه می‌آید و نه ثبت می‌شود؛ استثناهای پیش‌بینی‌نشده نیز پنهان نمی‌شوند.

این انتخاب هم از GuardClauses مورد تأیید مالک استفاده می‌کند و هم قرارداد نتیجه‌ای موجود را حفظ می‌کند. جایگزین‌ها عبارت‌اند از شرط‌های دستی، که وابستگی را حذف می‌کنند، یا اجازه‌دادن به استثناها برای خروج از کارخانه، که قرارداد غیرپرتاب‌شونده را می‌شکند. تبدیل همهٔ اعتبارسنجی‌ها به یک چارچوب عمومی هم برای این نیاز کوچک سود مشخصی نداشت.

بهترین نکتهٔ طراحی، کوچک‌ماندن محدوده است: نام trim یا نرمال نمی‌شود، قواعد طول یا یکتایی سراسری اضافه نمی‌شود، و ذخیره‌سازی، مجوز Vault، رویداد یا چارچوب نتیجهٔ عمومی ساخته نمی‌شود. `Ardalis.GuardClauses` بستهٔ واقعاً استفاده‌شده است؛ افزودن بستهٔ دیگری برای این عملیات ضرورتی نداشت.

## اعتبارسنجی و وضعیت فعلی

توضیحات PR موفقیت Restore، بررسی فرمت، ساخت Release بدون هشدار/خطا، ۱۸ آزمون NUnit (۷ آزمون معماری و ۱۱ حالت ساخت Asset)، اجرای Playground، `git diff --check` و یک بررسی CI را گزارش می‌کنند. این موارد را در این گزارش دوباره اجرا نکرده‌ام. بررسی مهارت شخصیِ ذکرشده در توضیحات PR خارج از مخزن بود و آزمون محصول محسوب نمی‌شود.

PR با commit `298b3da` در `main` ادغام شد. سند فعلی HV-05 نیز این برش را تکمیل‌شده می‌داند. کد فعلی از زمان این PR توسعه یافته است؛ این گزارش فقط تغییرات خود PR را توضیح می‌دهد، نه کل پیاده‌سازی امروز.
